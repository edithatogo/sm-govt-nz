# Bluesky Rollout Controller

Run non-posting preflight, request the bounded canary launch, reconcile the public URI/CID, activate four-per-day backfill, and advance only after the observation gate passes. Before selecting an agency, use `python scripts/bluesky_onboarding_agent.py plan`. After each operator-supervised attempt, record only a sanitized outcome with `python scripts/bluesky_onboarding_agent.py record <mirror_id> <outcome>`. Never record credentials, cookies, mailbox contents, challenge tokens, or verification URLs. The heuristic may rank candidates and browser plans, but cannot create accounts, submit challenges, post content, or change registry enablement. Before backfill, reconcile the mirror source allowlist against current public activity; a source with only stale records must be excluded from ongoing input while its historical records remain archived.
