# Bluesky Browser Onboarding Skill

Use a local SeleniumBase UC browser and attach Playwright over CDP for stable operator-supervised navigation. Fill the selected handle, unique password, and registration alias; stop for final submission and challenges. Reject any `.bsky.social` username label longer than 18 characters before opening the browser.

After operator completion, use `gogcli` against `edithatogo@gmail.com` to locate only messages addressed to the exact generated alias. Use a bounded query such as `gog gmail search -a edithatogo@gmail.com --readonly --json --results-only --max 10 "to:(<exact-alias>) newer_than:2d"`, then fetch only the matching message by ID. Open the verification target without printing, logging, committing, or persisting its URL. Do not navigate Gmail manually.

Age assurance is an operator checkpoint. The operator must provide any face scan, card authorization, government ID, CAPTCHA, or other sensitive proof. After verification, use `scripts/configure_bluesky_mirror_account.py` for profile setup, bot labeling, DID pin verification, DM-disabled app-password creation, and direct GitHub Environment provisioning. Do not use browser UI for post-registration configuration. Do not save browser storage, cookies, challenges, verification URLs, mailbox bodies, primary passwords, or app passwords.

Use the onboarding heuristic agent before each attempt. It learns from sanitized outcomes only and may choose between the headed UC/CDP plan, a headed standard-CDP fallback, and an operator checklist. It must stop at registration submission, CAPTCHA, age assurance, email verification, or any unexpected security challenge. One account per operator-supervised session remains the maximum; learning never enables bulk registration or bypasses platform controls.
